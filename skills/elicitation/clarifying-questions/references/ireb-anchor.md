## How this skill applies the practice

- Uses questioning as the elicitation technique of choice at the moment it is cheapest: before code exists, when a different answer still costs nothing to act on.
- Limits elicitation to the questions whose answers change the work, which is value-oriented depth applied to a single task.
- Checks shared understanding explicitly: the agent states what it would build (the recommended answer) and the person confirms or corrects it, instead of both sides assuming they agree.
- Records each answer with the person and date, so every requirement written from it has a source from the first minute.
- Keeps assumptions visible and separate from requirements, so a guess never enters the register as if a stakeholder had said it.

## What this skill deliberately leaves out

- Planned interviews with a script, capture sheet and summary: `interview-guide`.
- A complete quality walkthrough against a quality model: `quality-requirements`.
- Deciding the system boundary for a whole product: `system-context`.
